2. **Deficiencies & Failure Modes (R3 Requirement Gaps)**:
   - **Static "AI Online" Badge (`AIChatPage.tsx:283`)**:
     The header hardcodes:
     ```tsx
     <span className="text-xs text-emerald-400 font-medium">AI Online</span>
     ```
     This status indicator is static and does not reflect actual backend connectivity to Runpod or the mock service.
   - **No Offline / Local Mock Fallback Indicator**:
     When Runpod is offline or `RUNPOD_API_URL` is omitted, the backend server throws an error:
     ```typescript
     throw new TRPCError({
       code: "INTERNAL_SERVER_ERROR",
       message: "RUNPOD_API_URL is not configured"
     });
     ```
     The UI catches this and displays a raw error toast/bubble without switching to a graceful mock mode or displaying a "Operating in Local Fallback Mode (FAQ Only)" banner.
   - **No Mock Mode Toggle**:
     There is no UI control or environment-driven badge informing the user or tester whether responses are coming from the live Qwen/DeepSeek LLM or the deterministic fallback knowledge base.

## 3. Caveats

1. **Headless Execution Environment**: Visual layout verification was conducted through static code analysis, component inspection, and TypeScript compilation; visual rendering across specific browser viewports (mobile Safari, small Android screens) was not visually captured in a headless agent shell.
