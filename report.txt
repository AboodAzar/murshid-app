Graduation Project ReportPrepared by: Abdualrhman Abed & Noor Al-Huda HussainABSTRACTThe Murshid (مرشد) project is an intelligent, web-based academic advising platform designed specifically for the students and faculty at Al-Zaytoonah University of Jordan. By leveraging modern web technologies and advanced Artificial Intelligence (AI) using the Qwen 3.6 model, Murshid acts as a 24/7 personalized academic advisor. It aims to streamline the advising process, empower students to track their academic progress independently, and relieve the administrative burden on university staff. This document outlines the problem statement, product positioning, stakeholders, features, and the development timeline of the Murshid platform.1. Introduction1.1 Project DescriptionMurshid is an AI-powered intelligent academic advising platform designed to improve the university experience through advanced multi-agent AI technologies. The system automatically answers student inquiries, tracks academic progress, calculates GPA and completed hours, and identifies recommended courses in real time.The project integrates Artificial Intelligence, Web Technologies, and Cloud Infrastructure to create a complete academic advising solution. Murshid utilizes the massive context window of the Qwen 3.6:35B model in 8-bit quantization and a unique multi-agent architecture (including Data and Reroute agents) to provide natural, accurate, and on-topic advising while maintaining high-speed inference over the internet.The target users of the system include university students, academic advisors (doctors), and university administration. The success of the project will be measured through the detection accuracy of the AI, the speed of retrieving student data, and the reduction of repetitive queries directed at human advisors.1.2 Tasks and Project TimelineThe following table outlines the specific activities and tasks required to accomplish the objectives of the Murshid project.Table 1: Project TimelineWBSTask descriptionStart dateFinish dateProgress1Task 1: Research and Analysis (AI Model Selection)3/4/20243/17/2024100%2Task 2: Requirements Gathering3/18/20243/30/2024100%3Task 3: Design and Planning (Multi-Agent Architecture)4/1/20244/21/2024100%4Task 4: Implementation and Coding (UI, DB, Cloud)4/23/20245/23/2024100%5Task 5: Testing and Quality Assurance (Hallucination checks)5/24/20246/1/2024100%2. Positioning2.1 Business OpportunityUniversities currently suffer from significant bottlenecks during registration periods due to a high volume of repetitive student inquiries. By automating these interactions, universities can significantly optimize faculty time and improve student satisfaction, leading to better academic outcomes and smoother operations.2.2 Problem StatementIn the traditional academic advising system, several inefficiencies negatively impact both students and faculty:Repetitive Inquiries: University doctors and academic advisors spend a significant amount of their valuable time answering the exact same routine questions from hundreds of students (e.g., registration dates, prerequisite inquiries, and graduation requirements).Misallocation of Time: Because advisors are bogged down by these repetitive questions, they have less time to provide real, in-depth support to students who are facing complex academic or personal challenges that actually require human intervention.Limited Availability: Human advisors are only available during specific office hours, leaving students without immediate guidance when they are planning their schedules or making urgent academic decisions late at night or on weekends.2.3 Product Position StatementTo solve these problems, we developed Murshid, a platform that automates routine academic advising through an intelligent AI chatbot, paired with a comprehensive student dashboard.Automated Advising: Murshid instantly answers repetitive student questions accurately, freeing up university doctors to focus on students who need genuine human help.Personalized Dashboards: Students log in to see their real-time GPA, completed hours, remaining semesters, and enrolled courses, reducing the need to ask advisors for basic academic standing information.Secure and Official: The platform integrates a secure authentication system that strictly requires an official university email (@zuj.edu.jo or @std-zuj.edu.jo) to ensure privacy and exclusivity.3. Product Overview4.1 Product PerspectiveMurshid is a standalone, full-stack web application hosted securely on Google Cloud infrastructure. It acts as an intermediary between the university's academic data and the student. The technical foundation relies on:Frontend: React 19 with Vite, utilizing Tailwind CSS 4 and Framer Motion for responsive UI.Backend: Node.js and Express 4 routing through tRPC 11 for end-to-end type safety.Database: MySQL 8 hosted on a Google Cloud SQL instance, managed securely via Drizzle ORM.External APIs: The Resend API is utilized for strict @zuj.edu.jo email verification, and Runpod GPU instances are used for high-performance AI inference.4.2 Summary of CapabilitiesChoosing the Right AI Model was one of the most critical decisions in this project. The AI landscape is vast, and each model has its own strengths and weaknesses. After rigorous testing, we selected the Qwen 3.6:35B in 8-bit quantization model for several compelling reasons:Massive Context Window: It supports a context window of up to 1 million tokens, allowing the model to remember and understand the student's entire active conversation seamlessly.Hardware Efficiency: Using 8-bit quantization allows the massive 35 Billion parameter model to run efficiently on GPU instances (via Runpod) without sacrificing response quality, ensuring fast response times for students.Multimodal Capabilities: Its modern architecture supports both text and image processing. While the current version of Murshid focuses on text, this capability ensures the platform is future-proof and ready for image manipulation features planned for Version 2.Concurrent Usage: The system was engineered and hosted to support multiple students using the AI model at the exact same time without performance degradation.4.3 Assumptions and DependenciesThe system assumes users have an active internet connection.The system depends on Google Cloud for hosting and domain management.The system relies on the Resend API for delivering OTP verification emails securely.4.4 Self-Hosted LLM vs. Commercial APIs (ChatGPT / Gemini)A fundamental architectural decision for Murshid was choosing to self-host the Qwen 3.6:35B model on a dedicated Runpod server rather than simply relying on commercial APIs like OpenAI's ChatGPT or Google's Gemini. This decision was driven by three main factors:Data Security and Privacy: Commercial APIs require sending potentially sensitive university and student data to third-party servers. By self-hosting the LLM, we ensure that all student queries and academic data remain strictly within the university's controlled infrastructure, completely eliminating third-party data leakage risks.Full Modification Control: Commercial APIs are "black boxes" with strict, unchangeable guardrails. Self-hosting gives us full root-level access to modify the model's parameters, tweak inference configurations (like temperature and repetition penalties), and implement custom system prompts exactly how we want.High Technical Difficulty & Effort: While connecting to a ChatGPT API takes only a few lines of code, successfully hosting a massive 35 Billion parameter LLM locally is an extremely difficult engineering feat. It requires deep knowledge of GPU memory constraints (which is why 8-bit quantization was utilized), managing server load for concurrent users, and handling complex Linux/CUDA server maintenance. Taking on this challenging approach demonstrates a much higher level of engineering competence for this graduation project.5. Product FeaturesFeature 1: Multi-Agent AI System To ensure the AI strictly adheres to university guidelines, we built a highly optimized, multi-agent architecture rather than relying on a single prompt:Data Agent: Before the main model answers, a Data Agent searches and retrieves the most relevant university data, feeding the best-fit information to the main model to ensure high accuracy and fast data retrieval.Reroute Agent: A specialized agent continuously monitors the conversation. If a student tries to change the subject or go off-topic, the Reroute Agent ensures the AI seamlessly changes the topic within the app use case and prevents it from hallucinating.Robust Prompt Engineering: We crafted highly detailed system prompts so that the model consistently delivers excellent, natural-sounding responses, regardless of whether the student types a well-structured question or a poorly phrased one.Feature 2: Student Dashboard A personalized view of a student's academic standing, displaying completed hours, GPA, and graduation progress in real time.Feature 3: Bilingual Support Full support for English and Arabic with perfect Right-to-Left (RTL) UI consistency using modern CSS logical properties.6. Constraints and Difficulties FacedBuilding a production-ready AI platform from scratch presented several major challenges that we successfully overcame:Controlling AI Hallucinations: The toughest challenge was optimizing the prompts to ensure the model acted naturally while strictly preventing it from "hallucinating" or answering questions outside the provided university data. We solved this through the multi-agent system described above.Cloud Deployment and Accessibility: We wanted the project to be easily accessible over the internet rather than just running locally. We successfully purchased a domain name and configured Google Cloud to host the project, ensuring a reliable, public-facing web infrastructure.Database Reconnections: Transitioning the database from a local environment to a live, secure Google Cloud SQL instance required careful configuration of environment variables to maintain stable, persistent connections.Right-to-Left (RTL) UI Consistency: Ensuring the user interface looked perfect and did not break when switching between English and Arabic required rewriting the styling using modern CSS logical properties.Official Email Verification: Integrating the Resend email system to securely deliver One-Time Passwords (OTPs) while enforcing that only students with verified university emails could register required complex backend validation logic.7. ConclusionThe Murshid platform successfully demonstrates how modern AI can be practically applied within an educational institution. By handling routine inquiries, Murshid not only provides students with immediate, accurate, and personalized academic guidance, but it also restores valuable time to university doctors, allowing them to focus on meaningful mentorship and complex student needs.
